# Feature: WP-08 — entorno demo en el VPS

Hito 1 del maestro, el único que faltaba. Estado: **archivos escritos, sin verificar**.
Su criterio de aceptación exige un VPS y un dominio reales, que todavía no existen
(Q4 y Q1, decisión del dueño). Este documento no se cierra hasta desplegar de verdad.

## Specs

Entrecomillado = textual de `MAESTRO_PLATAFORMA.md`.

**S1 — Qué entrega WP-08.** «VPS con los requisitos de §14 (Q4), `compose.prod.yaml` con
Caddy y HTTPS para `demo.<dominio>` (Q1), proyecto de Compose `mw-demo` con su base y
sus secretos, `deploy-vps.yml` que despliega cada merge a `main`, contenedor `migrate`,
smoke test a `/readyz` y rollback.»

**S2 — Criterio de aceptación.** «un merge a `main` termina desplegado en el entorno
demo sin pasos manuales; una migración rota corta el deploy y deja la versión anterior
funcionando; `/readyz` responde 200 leyendo la base y la cola.»

**S3 — Los pasos del deploy (§14).** «1. Build y push de imágenes a GHCR con tag del
commit. 2. Por SSH al VPS: `docker compose -p mw-<entorno> pull && docker compose -p
mw-<entorno> up -d`. Las migraciones de Drizzle corren en un contenedor `migrate` antes
de levantar `api` y `worker`. 3. Smoke test a `/readyz` y rollback al tag anterior si
falla.»

**S4 — Regla de migraciones.** «solo aditivas ("expandir y después contraer"). Una
columna se borra en un PR posterior al que deja de usarla. Así un rollback nunca rompe
con la base.»

**S5 — Dos entornos, un VPS (D4).** «Dos entornos en el mismo VPS (D4), cada uno con su
proyecto de Compose, su base, sus secretos y su subdominio»: `demo.<dominio>`
automático con cada merge, `app.<dominio>` manual o por tag `v*` desde WP-70.

**S6 — Imagen única para api y worker (§5).** «`apps/api` y `apps/worker` usan la misma
imagen de Docker con distinto comando.»

**S7 — Requisitos del VPS (§14).** «Linux x86_64 o arm64, 4 vCPU, 8 GB de RAM y 80 GB de
disco como punto de partida. Docker y Compose.»

## Decisiones abiertas que este WP expone

**D-A — No hay artefacto de producción.** `apps/api` y `apps/worker` declaran
`"build": "tsc --noEmit"`: no emiten `dist/`. Hoy corren TypeScript directo con Node 24,
que ejecuta `.ts` quitando tipos. La imagen de este WP replica eso. Emitir de verdad
(exigiría `rewriteRelativeImportExtensions` y tocar cada paquete) es una tarea propia:
`TODO(decision)`.

**D-B — Docker en producción sí, en tests no.** ADR-0006 descartó Docker para la base de
integración local. §14 usa Compose en el VPS. No es contradicción —son problemas
distintos— pero queda escrito para que nadie lo lea como incoherencia: **Docker se usa
para desplegar, no para probar.**
