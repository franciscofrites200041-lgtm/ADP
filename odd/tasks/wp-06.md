# WP-06: Envelope encryption

Build the high-risk secret-encryption foundation required by WP-10 and WP-11.
Source of truth: `MAESTRO_PLATAFORMA.md` v3.0 §8 S1/S3 and WP-06 in §15. WP-06 continues over the existing code under D21.

## Specs
1. S1 — "La clave maestra (KEK) llega por la variable `MW_MASTER_KEY`: 32 bytes en base64. Tiene versión (`MW_MASTER_KEY_VERSION`) y nunca se guarda en la base ni en el repo."
2. S2 — "Cada workspace tiene su propia DEK de 32 bytes, guardada en `workspace_key` cifrada con la KEK (AES-256-GCM)."
3. S3 — "Cada secreto (key de proveedor, secreto de herramienta) se cifra con la DEK usando AES-256-GCM, un IV aleatorio de 12 bytes, y como datos asociados (AAD) `workspace_id:tabla:id`. Así no se puede mover un secreto de un workspace a otro."
4. S4 — "Rotación: se agrega una versión nueva de KEK y se re-envuelven las DEK con un script (`docs/runbooks/rotar-clave-maestra.md`). Las versiones viejas se leen hasta terminar la rotación."
5. S5 — "`createContainer` (y por lo tanto `apps/api` y `apps/worker`) se niega a arrancar si existe alguna variable de key de proveedor conocida (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `XAI_API_KEY`, `OPENROUTER_API_KEY`, `AI_GATEWAY_API_KEY` y la lista completa que documenta `pi-ai`)."
6. S6 — "Acepta: tests de cifrar y descifrar, AAD cambiado que falla, rotación de KEK, y arranque bloqueado con `OPENAI_API_KEY` presente."
