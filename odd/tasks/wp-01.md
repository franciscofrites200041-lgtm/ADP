# WP-01: Local environment

## Goal
Provide a reproducible local development environment with PostgreSQL 18, Caddy, and minimal web, API, and worker applications.

## Decision
`/readyz` in WP-01 confirms API readiness only. WP-02 will extend it with a PostgreSQL readiness check.

## Scope
- `infra/compose.dev.yaml` and `infra/Caddyfile`
- Minimal `apps/web`, `apps/api`, and `apps/worker` shells
- API `GET /healthz` and `GET /readyz` endpoints with tests
- Root development orchestration through pnpm and Turborepo

## Out of scope
- Database schema, migrations, and database readiness checks (WP-02).
- Authentication, business endpoints, UI flows, and production deployment.

## Tasks
- [x] T1 Map installed Turborepo and framework APIs, then define the development command contract.
  - Decision: use `turbo run dev` with a persistent, non-cached `dev` task; Node 24 native type stripping avoids an additional development runner dependency.
- [x] T2 Add the API shell and test-first liveness/readiness endpoints.
  - RED: the focused Vitest command failed while `src/app.ts` was absent.
  - GREEN: `apps/api/src/app.test.ts` verifies `/healthz` and `/readyz` through `app.request`; both return HTTP 200. The independent verifier also passed focused test, typecheck, lint, build, and a live port-3001 smoke test.
- [ ] T3 Add minimal web and worker shells and the local Compose/Caddy topology.
- [ ] T4 Wire the root development command and verify static checks plus local-service acceptance where Docker is available.
- [ ] T5 Record evidence and commit each reviewable work unit.

## Acceptance criteria
- `pnpm dev` starts the development topology.
- PostgreSQL 18 and Caddy are defined for local use.
- `GET /readyz` returns HTTP 200 before WP-02 database integration.
- API, web, and worker shells have explicit, minimal responsibility.

## Evidence
- T1: installed Turbo 2.11.7 documentation requires `dev` tasks to be persistent and non-cached; no persistent task will be placed in `dependsOn`.
- T2: `hono` 4.13.0 and `@hono/node-server` 2.1.0 are exact versions from MIDDLEWARE_MASTER.md §4. The API listens on port 3001; `GET /healthz` and API-only `GET /readyz` return 200. Verification: focused test, typecheck, lint, build, and live smoke all passed.
